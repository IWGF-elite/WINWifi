# Composition brief — live WinWiFi product tour

Build a ~68-second 16:9 software walkthrough from the actual WinWiFi React application. Use browser automation to load the app and navigate its real states with a visible cursor. The camera should move between full-app orientation and close detail, triggered by the interaction: aim, click, response, settle, then follow through to the next surface. Show live UI state changes rather than a slideshow of page captures.

Preserve WinWiFi's dark navy interface and blue/teal accents. Use crisp screen capture at 1920×1080/30fps, a restrained premium grade, focused camera pushes, a small pointer glow, real click states, and concise labels only when they add context. Use the actual product interface, not invented panels. Do not place “offline demo”, “training”, or development-status wording anywhere in the video or narration. Avoid unsupported live-sensor claims in narration.

Walk through: Command Center → Networks/search and selected AP details → RF Spectrum/band selection and plotted AP → Threats → Investigations/status and evidence → Forensics/PCAP filter and packet decode → Handshakes/EAPOL review → Reports/summary and export → branded close. Use controlled, realistic cursor paths and leave each response visible long enough to read.

Narration is in narration-script.txt. Use the selected HeyGen route after authentication, neutral international English, measured professional delivery, and line/word timing for captions. Mix a restrained electronic bed, sparse click/transition sounds, and narration with clear separation. End with “WinWiFi Security Auditor. Clear evidence. Focused analysis. Actionable reporting.”
